# Contributing

## Getting set up

```bash
git clone <this repo> && cd qphys
python3.11 -m venv .venv && source .venv/bin/activate
pip install -e '.[dev]'
pre-commit install

make test          # fast: no training, no seed sweeps
make lint          # ruff check + format check
make figures       # regenerate every figure from results/
```

`torch`, `qutip`, `pysindy` and `hmmlearn` are optional extras. Install
`torch` from **default PyPI**: `download.pytorch.org` has been observed to
return 403 through a proxy, so no index is hardcoded anywhere in this repo.

## The rules this project holds itself to

This topic attracts nonsense, so these are hard constraints rather than style
preferences. Each is here because breaking it produced a wrong result at some
point, and the story is in the README.

1. **Never claim a time series "is quantum."** The only claim under test is
   whether a model built from the quantum formalism is more efficient or more
   accurate than the best classical model *at matched capacity*. That is a
   modelling claim, not a physics claim.

2. **The null result is a deliverable.** Falsification machinery is built
   before models. The README's claims table must always contain a prominent
   statement of what was **not** shown; a PR that removes the last such row
   has broken the project regardless of what it added.

3. **Match capacity, not state count.** Compare at equal free-parameter count
   and say how you counted (see `qphys.common.metrics.free_params`, whose
   docstring carries the derivation). A model beaten by a *larger* model has
   not been beaten at matched capacity.

4. **Temporal split, declared before the first fit.** Never tune on test, and
   never shuffle a time series into a random split.

5. **Verify, do not assert.** Every number in the README comes from a cell
   that ran. Tables live in `results/` and are regenerated, never typed.

6. **At least five seeds, with the failure rate reported.** Single-seed
   results are not results. This rule has already paid for itself here: one
   HQMM fit scored 0.8464 and appeared to overturn the headline, while the
   same configuration over five seeds averages 0.8785 ± 0.0267.

7. **Pre-declare convergence criteria.** Discarding a run is legitimate only
   against a threshold fixed in advance, on *training* loss, never on the
   answer (`qphys.common.seeding.CONVERGENCE_REL_LOSS`). If the data carries
   noise, gate the **excess over the noise floor**, since a fixed absolute
   threshold is unreachable by construction above about 2% noise.

## Adding an experiment

Logic lives in `src/`. A notebook imports it and is never the source of
truth. An experiment that produces a number for the README writes a CSV into
`results/`, and the figure that shows it is generated by
`qphys.common.figures`.

If you add a claim to the README, add the test that fails when it stops being
true. `tests/test_acceptance_seattle.py` is the pattern: it asserts the
README's claim and its failure message says *update the README, not this
test*.

## Charts

Colour is computable, so it is computed:

```bash
make palette     # lightness band, chroma floor, CVD separation, contrast
```

Use `qphys.common.plotting`. Categorical hues are assigned in fixed order and
never cycled; a reference or ground-truth line is muted ink rather than a
categorical hue, because it is not competing with the data; text wears ink
tokens, never the series colour. Any chart with two or more series carries a
legend **and** direct labels, so identity is never colour alone.

## Commits and PRs

- One logical change per commit; the message says *why*, the diff says what.
- CI must pass: ruff, ruff-format, and the offline test subset.
- If a measured number changes, re-run the experiment, regenerate the figure,
  and say so in `CHANGELOG.md`.
